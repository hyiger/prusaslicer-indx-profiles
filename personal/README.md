# Personal filament presets

Not part of the generated set. These are exports from the author's own
[Filament DB](https://github.com/hyiger/filament-db) app — see the `# PrusaSlicer
config bundle generated by Filament DB` header on each file — for filaments Prusa
does not publish an INDX profile for. They are kept here because they are useful,
not because they are derived from anything in `PrusaResearch.ini`, and none of the
provenance discipline in `../CLAUDE.md` applies to them.

**They do not import into stock PrusaSlicer as they stand.** Each carries two
keys no PrusaSlicer build defines:

| Key | Where it comes from |
|---|---|
| `activate_air_filtration` | an Orca/Bambu key with no PrusaSlicer equivalent |
| `filamentdb_id` | only exists in the [Filament Edition fork](https://github.com/hyiger/PrusaSlicer) |

`PresetBundle::load_configbundle` calls `set_deserialize` with no unknown-key
tolerance (`PresetBundle.cpp:1609`, throwing at `Config.cpp:531` and rethrown at
1625), unlike the plain config-INI path, which catches and ignores
`UnknownOptionException`. So **File → Import → Import Config Bundle** aborts with
`Invalid configuration bundle … section [filament:…]` and imports nothing.

**Do not drop one into `<datadir>/filament/` unchanged.** That path is
`ConfigBase::load_from_ini` → `read_ini` → `ConfigBase::load(tree)`, and
`ConfigBase::load` iterates only the *top level* of the tree
(`Config.cpp:741-751` at `version_2.9.6`). `read_ini` nests every key one level
down under the `[filament:…]` section, so the loop sees a single node named
`filament:<Name>`, fails to recognise it, ignores it, and applies **no keys at
all**. `load_presets` then lays that empty config over PrusaSlicer's defaults, so
you get a preset named after the file with every value at the compiled-in
default — nozzle 200 °C, bed 0 °C — and nothing is logged. It is the same trap
`../CLAUDE.md` documents under "User preset files on disk must be fully
flattened", and for a PC, TPU or PP preset it is a silently wrong print.

One way to use them today:

- **Delete the `[filament:<Name>]` header line** so the keys sit at the top
  level, and name the file `<Name>.ini` — `load_presets` takes the preset name
  from the filename stem, spaces included. Then drop it into
  `<datadir>/filament/`. Now `ConfigBase::load` sees every key, applies the real
  ones and ignores the two unknown ones. This works because each export is
  already fully flattened: every one carries all 66 keys of a resolved Prusa
  INDX filament preset (`Siraya_Tech_TPU_64D.ini` lacks only `filament_notes`,
  which defaults to empty).

The [Filament Edition fork](https://github.com/hyiger/PrusaSlicer) is not a
second route: it defines `filamentdb_id`, but not `activate_air_filtration`, so
bundle import still aborts there too.

The real fix belongs in the Filament DB exporter: stop emitting
`activate_air_filtration`, and emit `filamentdb_id` only for the fork. Do not
hand-edit these files — they are regenerated by that app, and an edit here is
lost on the next export.
